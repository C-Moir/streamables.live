// Sovereign Data Architecture

Research - In Progress

The foundation layer for any AI system that is genuinely aligned with the humans using it. If the data isn't owned by the user, the intelligence built on top of it isn't either.

Current areas of exploration: local-first storage architectures where data never leaves the user's environment by default; encrypted sync protocols that allow portability without exposure; and self-sovereign identity primitives that let individuals prove claims about themselves without relying on a third-party identity provider.

The practical goal: a reference architecture for a personal data environment that any developer could implement and any user could own outright.

Local-first Self-sovereign Identity Encrypted Sync

// Multi-Agent Orchestration

Research - In Progress

Most AI tools are built as a single assistant you talk to. The more powerful model is a network of specialised agents - each with defined scope, persistent memory, and specific tooling - working in coordination under the user's authority.

The research focuses on: orchestration patterns for routing tasks between agents; shared memory architectures that preserve context across sessions without centralising it; conflict resolution when agent outputs disagree; and keeping human oversight meaningful as agent autonomy increases.

Practical output will be an open architecture for a personal agent runtime - self-hosted, locally governed, extensible.

LLM Orchestration Agent Memory Human-in-the-loop

// On-Chain Reputation Models

Research - In Progress

Digital reputation is currently owned and controlled by platforms. It doesn't travel with you, it can be manipulated, and it disappears when the platform does. This research explores what verifiable, portable, tamper-resistant reputation looks like when it's built on-chain.

Core questions: how do verifiable on-chain actions compose into a reputation score? What makes a reputation claim credible without exposing private data? How do you design an accountability system that is useful for legitimate actors and unusable by bad ones?

Connected to the Karmic Ledger prototype in Projects and the Reputation Problem article in Articles.

// AI Adoption in SMEs

Research - New

Enterprise AI adoption gets most of the coverage. SME adoption - particularly in service industries - is where most of the real friction lives, and where most of the interesting implementation problems are.

This research documents what's actually happening on the ground: which tools get adopted and which get abandoned, what drives the decision to implement, what causes implementations to fail, and what the operational environment in hospitality and service businesses demands that most AI tools don't account for.

Feeding directly into the AI Implementation consulting work and the AI in Hospitality article.

// Sovereign Agent Framework

Project - Research

An early-stage exploration of personal multi-agent AI - systems where multiple specialised agents collaborate under a single user's control. The core problem: most AI tooling is designed to serve the platform, not the user.

A sovereign agent system inverts this. Your agents, your data, your rules. The orchestration layer routes tasks to the right agent, maintains context across sessions, and keeps decision authority with the human - not the API provider. Early architecture on GitHub.

// Karmic Ledger Prototype

Project - Prototype

Online reputation is broken. Platforms control it, game it, or delete it without warning. The Karmic Ledger is a prototype for what accountability looks like when it's on-chain - reputation scores built from verifiable actions, not self-reported profiles or follower counts.

Every meaningful interaction between parties leaves an immutable trace. Over time, those traces compose into a reputation that's portable, auditable, and impossible to fake at scale. Conceptual prototype - architecture documented in research notes.

// Background

Two decades spent inside hospitality - starting on the floor, moving into operations, then systems and process design at scale. The kind of experience that teaches you what actually breaks under pressure, and why most software built for the industry misses the point.

That background became the entry point into technology. When you've spent years fixing operational problems with whatever tools exist, you develop strong opinions about what good systems look like - and a low tolerance for complexity that doesn't earn its place.

The shift to AI consulting was a natural extension. The problems are different, but the discipline is the same - understand the environment, simplify where possible, and build things that hold up in the real world.

// Philosophy

  • Accountability should be built into architecture - not added as a feature after the fact
  • The people using the tools should be the ones who own the data they generate
  • Complexity is a liability - good systems do more with less
  • AI is most useful when it augments human judgement, not replaces it
  • Transparency builds trust - building in public is a practice, not just a posture

These aren't abstract principles. They show up in every system we design, every tool we recommend, and every project we take on.

Streamables - ideas, data, and systems in motion. A stream is directional but adaptive. It doesn't stop - it finds a way through. That felt like the right metaphor for how this work moves.

.live - not a finished product. A live environment. Active, in-progress, and in contact with the real world. The dot-live extension was chosen deliberately over dot-com - it signals something different. Something present tense.
