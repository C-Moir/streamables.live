lean-ops

Live — v1.0.0
→ View on GitHub
//

lean-ops is a Claude Code skill that reduces token usage and tool call overhead on any task — research, file operations, web lookups, or multi-step work. It applies by default. You don't invoke it manually. It just changes how Claude operates.

Every tool call costs tokens and time. Most AI assistants burn them carelessly — sequential lookups when parallel would do, full file reads when a grep would find the answer in one shot, crawling five sites when one aggregator has everything. lean-ops fixes that systematically.

// claude code — lean-ops active
# without lean-ops ▶ WebSearch("X version") → wait → WebSearch("Y docs") → wait → WebSearch("Z price") 3 sequential calls. 3x latency. 3x context consumed.
# with lean-ops ▶ WebSearch("X version") + WebSearch("Y docs") + WebSearch("Z price") ✓ 1 round trip. Same results. Context preserved.
# file lookup — without lean-ops ▶ Read("src/bigfile.ts") // 2,000 lines consumed scanning manually for functionName...
# file lookup — with lean-ops ▶ Grep("functionName", "src/") → Read offset:142 limit:30 ✓ 30 lines. Targeted. Done.

// the difference compounds across a full session

The Core Rule

Plan before you act. Before making a single tool call, identify the minimum set of operations required to complete the task. Execute that plan — in parallel where possible.

Never react. Never search-then-search-again because the first result was incomplete. Know what you need before reaching for a tool.

Research Operations

Aggregators over crawlers

For any lookup — packages, documentation, availability — find the single source that consolidates the data rather than hitting individual sites. npmjs.com for npm packages. pypi.org for Python. crates.io for Rust. caniuse.com for browser support. The official docs URL directly instead of search engines. One fetch beats five.

Parallel by default

Any independent pieces of information get fetched simultaneously — not one at a time. The only exception is when one call's output determines the next call's input.

Stop when you have enough

The goal is a correct answer, not an exhaustive survey. If the first result answers the question, stop. Fetching three more sources to confirm something already confirmed is waste.

File Operations

Skip noise directories

node_modules, .git, dist, build, __pycache__, .venv — never searched, never read, unless explicitly asked. These are generated artefacts. They pollute results and burn context.

Grep before read

Looking for a function, class, or pattern? Grep first. Only read the file if you need surrounding code the grep didn't capture. Never read a 2,000-line file to find one function when a targeted search takes a second.

Read minimally

Large files get read with offset and limit — only the relevant section. Never re-read a file you just edited. The edit tool confirms success. Re-reading is a wasted call.

Context Window Awareness

The context window is finite. Treat it like RAM — don't page in data you won't use. Targeted reads over full reads. Facts extracted from documents, not documents repeated back in full. Decisions front-loaded so there are fewer corrective calls mid-task.

If the conversation is long, earlier tool results may have been compacted. Re-read only what's actually needed, not everything previously touched.

Output Economy

Response length matches task complexity. A yes/no question gets a sentence. A factual lookup gets the fact. A complex implementation gets full detail. No padding. No summary of what just happened — the user can see the tool calls. No "next steps" section unless asked.

The Install

lean-ops ships as a Claude Code plugin. One command and it's active across every session.

// install
$ claude plugin install github:C-Moir/claude-lean-ops ✓ lean-ops installed. Applies by default.

// no configuration required

Or add it manually to ~/.claude/settings.json under enabledPlugins. The skill loads at session start and applies across all tasks without invocation.
